# vFGI 응답의 현실성 평가·향상 방법 연구

> **목적**: vFGI 페르소나가 생성한 응답이 실제 한국 금융 고객의 발언과 얼마나 가까운지 측정하고, 그 거리를 줄이는 방법을 데이터셋 특성에 기반해 설계한다.
>
> **기반 데이터셋**: NVIDIA Nemotron-Personas-Korea (CC BY 4.0)
>
> **타겟 응용**: iM뱅크 신상품·UX·정책·브랜드 검증의 의사결정 가속기

---

## 1. 데이터셋 특성 재정의

본 연구의 출발점은 데이터셋이 가진 **강점**과 **공백**의 정직한 매핑이다. 응답의 현실성을 향상시키는 모든 방법은 강점을 증폭시키거나 공백을 보완하는 것이어야 한다.

### 1.1 강점 — 그대로 활용해야 할 5가지

| # | 강점 | 응답 현실성에의 함의 |
|---|---|---|
| **S1** | 252개 시군구 × 17개 시도 단위 지역 세분화 | "광주 서구 70대 자영업자" 식 미시 세그먼트가 가능. 답변 톤·관심사·소비 행태가 지역에 따라 갈라질 수 있는 **유일한 한국형 대규모 데이터** |
| **S2** | 공식 1차 통계 기반 (KOSIS, 대법원, 보건공단, 농촌경제연구원) | 인구·가구·소득 분포가 **임의 추정이 아닌 실측치**. 합성 결과의 분포가 KOSIS 와 차이 나면 명시적 캘리브레이션 가능 |
| **S3** | 확률적 그래프 모델(PGM)로 변수 간 결합분포 학습 | 변수 간 일관성(예: 80대 여성 비중 1.52배, 50대 후반 사별 패턴) 자체에 **PGM 기반 보정**이 들어가 있음 |
| **S4** | 13개 다층 페르소나 (직업·스포츠·예술·여행·음식·가족·종합 + 6개 속성) | 한 사람당 의사결정 동인까지 추론 가능. **금융 응답이 다른 라이프스타일 레이어와 모순되지 않는지** 자기 검증 데이터로 사용 가능 |
| **S5** | 79% 동명이인 + PGM 결합분포 | 표본의 다양성과 현실 분포 모두 반영. 대규모 N 추출 시에도 표본 편향 적음 |

### 1.2 공백 — 응답 현실성을 떨어뜨리는 4가지 요인

| # | 공백 | 응답 현실성에의 함의 |
|---|---|---|
| **G1** | 자산·소득 디테일·금융상품 보유 미포함 | 본 시스템의 핵심 도메인인 금융 응답 시 **추측에 의존**. "월 소득 X만원·청약 보유·신용카드 2장" 같은 세부 정보가 페르소나 카드에 없으면 LLM 이 클리셰로 채움 |
| **G2** | 변수 간 교호작용 미반영 | 단일 변수의 분포는 정확하지만 **상호작용 효과** (예: 50대 자영업 × 대구 거주 → 카카오뱅크 수용도) 는 학습되지 않음 |
| **G3** | 18세 미만 부재 | 청소년 대상 상품 검증 불가능 |
| **G4** | 젠더 정체성·성지향성 등 LGBTQ+ 차원 부재 | 다양성 평가 시 사각지대 |

### 1.3 LLM 측 추가 위험 — 응답 현실성 저해 요인 3가지

| # | 위험 | 효과 |
|---|---|---|
| **L1** | LLM base bias가 페르소나 톤을 덮어씀 | 50대 자영업자 톤으로 답해야 하는데 LLM 표준 어조로 답하는 클리셰 |
| **L2** | "모범 답안" 회피 본능 | 부정적 의견·반박을 드러내지 않고 두루뭉술하게 답하는 경향 |
| **L3** | Mode collapse | 8명 패널의 답이 톤·내용 모두 비슷해지는 현상 (LLM 의 attractor 가 동일) |

## 2. "현실성" 의 7차원 분해

응답 현실성을 단일 지표로 보면 측정·개선 모두 막연해진다. 다음 7개 차원으로 분해한다.

### 2.1 인구학적 일관성 (Demographic Consistency)
페르소나의 연령·지역·직업·가구·학력에 모순되는 진술이 없는가.
- **나쁜 예**: 70대 농촌 자영업자가 "넷플릭스 구독료가 부담돼서" 라고 발화
- **좋은 예**: 70대 농촌 자영업자가 "우체국 적금 만기 됐을 때 이장님이 추천해줘서" 라고 발화

### 2.2 언어적 정합성 (Linguistic Authenticity)
세대·지역·직업에 맞는 어휘·문체·어조가 사용되었는가.
- 측정 가능 마커: 사투리, 한자어 vs 외래어 비율, 존댓말·반말, 발화 길이 분포
- **나쁜 예**: 50대 대구 자영업자가 표준어로 영어 외래어 섞어 발화
- **좋은 예**: "그건 좀 아인 거 같은데, 우리 가게 손님은 그런 거 안 좋아하지"

### 2.3 상황적 정박성 (Situational Anchoring)
답변이 본인의 가족·일·재정 상황에 자연스럽게 박혀 있는가, 아니면 추상적 일반론인가.
- **나쁜 예**: "저는 적금을 결정할 때 금리를 가장 중요시합니다" (누구나 할 수 있는 답)
- **좋은 예**: "이번에 큰애 대학 등록금이 다음 학기에 빠져나가야 해서, 만기를 12개월로는 못 잡아요"

### 2.4 응답 다양성 (Response Diversity)
8명 패널의 답변이 충분히 구별되는가, 아니면 mode collapse 가 발생하는가.
- 측정: pairwise 응답 임베딩 유사도, 토픽 클러스터의 패널 분포
- **나쁜 예**: 8명 모두 "출석 우대가 부담스럽다" 톤으로 수렴
- **좋은 예**: 디지털 친화 30대 = "재미있을 것 같다", 60대 시니어 = "매일 들어가는 게 귀찮다", 자영업 사장 = "장사 바쁠 땐 못 챙긴다"

### 2.5 정성적 반박·교차 발화 (Cross-Talk Realism)
실제 FGI 의 핵심은 패널 간 의견 충돌·동의·심화. 가상 패널이 이걸 흉내내는가.
- **나쁜 예**: 진행자 질문 → 패널 1, 2, 3 차례로 답 → 끝
- **좋은 예**: 패널 1 발화 → 패널 3 이 "그건 우리 동네에선 좀 다른데..." 라며 반박 → 패널 5 가 패널 1 편들기

### 2.6 정량 일치율 (Quantitative Calibration)
같은 자극물에 대한 vFGI 결과의 정량 메트릭(수용도, NPS, 우대조건 선호도 등)이 실제 FGI/설문과 얼마나 일치하는가.
- 측정: Pearson r, RMSE, 분포 KL divergence
- 이미 v2의 Calibration Mode 가 부분 구현. 더 정교한 자동 보정이 필요.

### 2.7 세그먼트 차이의 정확성 (Segment-Difference Accuracy)
서울 vs 대구, 30대 vs 50대 등 세그먼트별로 vFGI 가 만들어내는 차이가 **실제 통계 패턴**과 일치하는가.
- **결정적 차원** — Design Doc 의 narrowest wedge ("서울과 대구는 다르다") 가 정확하지 않으면 vFGI 의 가치 명제가 무너짐.
- 외부 벤치마크: KOSIS 가구금융복지조사, 한국갤럽 금융 트렌드 리포트, KDI 지역경제 보고서

## 3. 평가 방법론 (Evaluation Methods)

### 3.1 Tier 1 — 자동·내장 평가 (개별 Run 마다)

#### M1. **인구학 일관성 점수** (Demographic Consistency Score, DCS)
**원리**: LLM 자체 검증 + 룰 기반 검출.

```
For each speak event:
  - persona card 추출 (연령·지역·직업·가구·소득·학력)
  - LLM judge: "이 발화가 위 페르소나 카드와 모순되는 점이 있는가? 0~10점."
  - 룰 기반 검출:
    · 연령 모순 어휘 (70대가 "TikTok에서" 등)
    · 직업 모순 (전업주부가 "퇴직금 굴리려고")
    · 지역 모순 (대구 거주자가 "한강 산책길에")
DCS = mean(LLM judge score) - 0.5 * count(rule violations)
```

**구현 위치**: `lib/agents/realismJudge.ts` (신규), `event` 테이블에 `dcsScore` 컬럼 추가.

#### M2. **언어적 다양성 지수** (Linguistic Diversity Index, LDI)
**원리**: 발화 length 분포 + Type-Token Ratio + 사투리 마커 카운트.

```
LDI = α * std(speak_length) / mean(speak_length)         # 발화 길이 분산
    + β * mean(TTR per speak)                            # 어휘 다양성
    + γ * dialect_marker_density                         # 지역 어휘 밀도
    - δ * shared_vocabulary_overlap                      # 8명 발화 간 단어 중복도
```

**구현**: 발화 후처리 파이프라인에 형태소 분석기(KoNLPy 또는 Mecab) 또는 LLM 기반 마커 추출.

#### M3. **응답 다양성 점수** (Response Diversity Score, RDS)
**원리**: 패널 간 발화 임베딩의 평균 pairwise cosine 거리.

```
embeddings = embed([speak_1, speak_2, ..., speak_N])
RDS = mean over pairs (i,j) of (1 - cos(emb_i, emb_j))
threshold: RDS > 0.35 → 양호. 0.20 미만 → mode collapse 의심.
```

**구현**: `voyage-3-large` 또는 OpenAI `text-embedding-3-large` 로 발화 임베딩 (Vercel AI SDK 지원).

#### M4. **상황적 정박성 점수** (Situational Anchoring Score, SAS)
**원리**: 발화 텍스트에서 페르소나 카드 정보 인용 횟수 계산.

```
For each speak:
  Count direct/indirect references to persona attributes
  (자녀 이름·연령, 직장, 동네, 취미, 가족 구성 등)
SAS = mean references per speak
좋은 vFGI: SAS ≥ 1.5 (한 발화당 평균 1.5개 이상의 페르소나 디테일 인용)
나쁜 vFGI: SAS < 0.5 (대부분 추상적 일반론)
```

### 3.2 Tier 2 — 외부 벤치마크 비교 (Calibration)

#### M5. **실제 FGI 비교** (이미 v2 구현, 확장)
- 동일 자극물의 vFGI 결과 vs 외부 리서치 회사 보고서
- 메트릭: 수용도 Δ, 매력·장벽 Jaccard 유사도, 토픽 임베딩 정렬 점수
- 임계값: 일치율 70%+ = 의사결정 근거 활용 가능, 50-69% = 조건부, <50% = 보완 필요

#### M6. **공개 통계 분포 일치** (KOSIS Cross-Check)
- 자극물에 따라 다른 외부 벤치마크 사용
  - 금융상품 → 한국갤럽 "금융신뢰도 조사", KOSIS "가구금융복지조사"
  - 모바일 앱 UX → 컨슈머인사이트 "은행 앱 만족도 조사"
  - 지역 차이 → 한국은행 "지역경제 보고서"
- vFGI 결과의 세그먼트 차이가 외부 통계와 같은 방향인지 확인

### 3.3 Tier 3 — 인간 평가 (Sample Audit)

#### M7. **블라인드 비교 테스트**
- 실제 FGI 발언록 5개 + vFGI 발언록 5개 → 도메인 전문가(상품기획·UX 리서처)가 어느 게 어느 것인지 맞히기
- Turing-style 테스트. 정답률이 50% 에 가까울수록 vFGI 가 인간과 구별 안 됨 = 현실성 높음

#### M8. **부부장 검증 루프**
- 5건의 vFGI 결과를 부부장(wedge 고객)에게 보여주고 "당신이 직접 인터뷰한 것 같은가?"  Likert 평가
- 본인이 안 믿으면 임원도 안 믿음. 가장 강력한 인간 평가.

## 4. 향상 방법 (Enhancement Methods) — 데이터셋 특성 기반

### 4.1 강점 증폭 (Amplify Strengths)

#### E1. **13개 페르소나 레이어 전부 프롬프트 주입** (S4 활용)
**현재**: orchestrator 가 페르소나당 약 7~8개 필드만 프롬프트에 포함.
**제안**: 13개 레이어(직업·스포츠·예술·여행·음식·가족·종합 + 6개 속성) **전부 주입** + 패널리스트 시스템 프롬프트에 "이 13개 레이어 중 최소 2개를 발화마다 인용하라" 규칙 추가.

```typescript
// lib/orchestrator.ts panelBlock 확장
const layers = [
  "professional_persona", "sports_persona", "arts_persona",
  "travel_persona", "culinary_persona", "family_persona",
  "persona", "cultural_background", "skills_and_expertise",
  "hobbies_and_interests", "career_goals_and_ambitions"
];
```

**기대 효과**: SAS(상황적 정박성) 0.5 → 1.5+

#### E2. **시군구 단위 정보 주입** (S1 활용)
**현재**: province·district 정보만 텍스트로.
**제안**: 시군구 단위 외부 사전 추가
- 시군구별 인구·평균소득·산업 구조 (KOSIS)
- 시군구별 주요 음식·관광지·랜드마크
- 시군구별 사투리 마커
→ 페르소나 컨텍스트에 자동 주입

```typescript
// lib/persona/districtContext.ts
const DISTRICT_CONTEXT = {
  "광주-서구": {
    landmarks: ["치평동 카페거리", "상무지구"],
    industries: ["금융", "유통"],
    dialect: "전라도",
    notable_food: ["비빔밥 골목", "오리탕"]
  },
  ...
};
```

**기대 효과**: 언어적 정합성·상황적 정박성 동시 향상.

#### E3. **사투리·세대 어휘 사전** (S1 활용)
**제안**: 5개 권역(영남·호남·충청·강원·제주) × 4개 세대(2030/4050/6070/80+) = 20셀 사투리·세대 어휘 사전 구축.
- 영남 50대: "그래갖고", "와이러노", "디게"
- 호남 70대: "긍께", "워매", "거시기"
- MZ 30대: "찐", "갓생", "MZ"

페르소나 카드의 region × age 셀에 따라 패널리스트 프롬프트에 동적 어휘 힌트 주입. 단, **강제하지 않음** — "자연스러우면 사용하라" 수준.

**구현**: `lib/persona/dialectLexicon.ts` (정적 JSON) + orchestrator 프롬프트 확장.

#### E4. **PGM 보정 활용** (S3 활용)
데이터셋이 이미 PGM 으로 결합분포를 학습했으므로, **샘플링 시 PGM 분포를 그대로 따름** — 즉 인위적 권역 쿼터를 너무 강하게 강제하지 말고, PGM 분포에 가깝게.

**제안**: `samplePanel` 에 "natural" 모드 추가. quota 강제 대신 PGM 분포 맞춤. 의도적 oversample 이 필요한 케이스(예: 80대 비중 강제 30%)에만 quota 사용.

### 4.2 공백 보완 (Fill Gaps)

#### E5. **금융 행동 합성 레이어** (G1 보완) — 핵심
**현재**: 페르소나 카드에 금융 행동 데이터 없음. LLM 이 클리셰로 채움.
**제안**: 통계청 가구금융복지조사·한국은행 가계금융조사 분포를 사용해 페르소나 ID 별로 **금융 행동 합성 레이어 1회 생성·캐싱**.

```typescript
// lib/persona/financialContext.ts
type FinancialContext = {
  monthlyIncomeRange: string;     // "300~400만원"
  assetsRange: string;             // "1억~3억"
  debtsRange: string;              // "0~5천만원"
  primaryBank: string;             // "신한"  
  secondaryBank: string[];         // ["카카오뱅크", "토스뱅크"]
  hasMortgage: boolean;
  hasCreditCard: boolean;
  cardCount: number;
  riskAversion: "low" | "medium" | "high";
  digitalLiteracy: "low" | "medium" | "high";
};

// 페르소나의 age·region·occupation·housing 으로 결합분포 추출 후 합성
async function synthesizeFinancialContext(persona: Persona): Promise<FinancialContext>
```

데이터 출처:
- 한국은행 「2024 가계금융복지조사」 (소득·자산·부채 분포)
- 한국은행 「2024년 지급결제동향」 (카드·송금 행동)
- 금감원 「2024년 금융이해력 조사」 (디지털 리터러시)

페르소나당 1회 합성 후 DB 캐시(persona.fields.financial). 모든 vFGI 에서 재사용.

**기대 효과**: 금융 응답의 클리셰 → 구체적 금액·은행 이름·상품 보유 인용. SAS·DCS 동시 향상.

#### E6. **변수 교호작용 보강** (G2 보완)
**현재**: 단일 변수 분포는 정확하나 교호작용 없음.
**제안**: 외부 통계(예: 「가계금융복지조사」의 권역×연령×소득 cross-tab)를 활용해, 자주 묻는 자극물 도메인(금융상품 수용성, 모바일앱 사용성)에 한해 **사후 보정**.

방법:
- N건의 실제 FGI 결과 + vFGI 결과 페어 → 부적합 응답 패턴 학습 → 프롬프트 룰로 추가
- Bayesian update: vFGI 결과 → KOSIS 통계로 posterior 보정

이건 v3 후반부 R&D. 지금 당장은 필요 없음.

### 4.3 LLM 위험 대응 (Mitigate L1-L3)

#### E7. **Multi-shot Persona Conditioning** (L1, L3 대응)
**제안**: 인터뷰 시작 전 각 패널이 "자기 소개 한 문장 + 일상 한 장면" 을 먼저 발화하도록 워밍업 라운드 추가. 그 자기 소개를 다음 발화의 in-context anchor 로 사용.

**현재 코드** (`prompts/system/moderator.md`) 워밍업 섹션 강화:
```
Section 1 (warmup) 에서 각 패널이 다음 형식으로 자기소개:
"안녕하세요, [이름]입니다. [지역] 살고 [직업] 합니다.
요즘 일상은 [구체적 한 장면 — 페르소나 카드 인용]."
이 자기소개가 이후 모든 발화의 어조·관점·디테일의 anchor 가 됩니다.
```

**기대 효과**: RDS(응답 다양성), DCS, SAS 동시 향상.

#### E8. **반박 강제 프롬프팅** (L2 대응)
**제안**: 진행자 시스템 프롬프트에 "각 섹션마다 최소 1회 패널 간 반박 또는 보완 발화를 유도하라" 규칙 추가. 이미 SSE event 에 `crosstalk` type 정의되어 있음 — 적극 활용.

```
규칙: 패널 N의 발화 후 다음 중 하나를 트리거:
1. 다른 패널이 "그건 좀 다른데..." 라며 반박
2. 다른 패널이 "맞아요, 저도 그런데..." 라며 보완
3. 진행자가 "OO님이 방금 한 말과 다른 의견 있으신 분?" 으로 유도
```

**기대 효과**: Cross-talk realism (2.5 차원) 향상.

#### E9. **자기검증 루프** (L1 대응)
**제안**: 발화 생성 후 별도 LLM call 로 "이 발화가 페르소나 카드의 다음 5가지 속성과 모순되는가?" self-check. 모순 발견 시 발화 재생성 또는 표시.

비용 부담 큼 → 옵션 토글로 제공 ("정밀 모드"). 비용 2~3배 증가하나 DCS 0.85 이상 보장.

### 4.4 평가 자동화 인프라

#### E10. **realism 메트릭 dashboard**
- Run 별 자동 측정: DCS, LDI, RDS, SAS, 4지표
- Study 통합 PDF 의 "방법론" 섹션에 본 Run 의 4지표 게이지 표시
- 임계값 미달 시 PDF 에 경고 ("⚠ 응답 다양성 RDS=0.18, mode collapse 의심. 재실행 권장")

#### E11. **Calibration 풀 구축**
- iM뱅크 사내에서 진행한 실제 FGI 보고서를 익명화 후 누적 (현재 Calibration Mode 가 1건씩 처리)
- 50건 이상 누적 시 vFGI 의 보정 계수 자동 학습
- 보정 계수: 권역별·자극물 종류별·연령대별 systematic bias

## 5. 우선순위 및 로드맵

| 단계 | 기간 | 작업 | 기대 효과 |
|---|---|---|---|
| **Phase A — Quick Wins** | 1~2주 | E1 (13 layer 주입), E2 (시군구 컨텍스트 사전), E7 (워밍업 자기소개), E8 (반박 강제), M1+M3+M4 (DCS/RDS/SAS 자동 측정) | 기존 v2 위에 응답 품질 즉시 향상 |
| **Phase B — 금융 도메인 보강** | 3~5주 | E5 (금융 행동 합성), M5 확장, M6 (KOSIS 자동 비교), 사투리 사전 E3 | 금융 도메인 응답 현실성 결정적 향상. iM뱅크 use case 정조준 |
| **Phase C — 대규모 검증** | 8~12주 | E11 (Calibration 풀 50+), M7 (블라인드 비교), M8 (부부장 루프 5회 누적), E6 (교호작용 보정) | 외부에 "실제 FGI ±X% 정확도" 공개 가능한 수준 |
| **Phase D — Production R&D** | 6개월+ | LLM fine-tuning on calibrated transcripts, 자체 평가 모델 학습 | vFGI 가 외부 리서치 회사를 일부 영역에서 대체 가능한 수준 |

## 6. 가장 임팩트 큰 첫 5가지 (당장 시작)

1. **E1 — 13 페르소나 레이어 전부 프롬프트 주입** (1일)
2. **E5 — 금융 행동 합성 레이어 (페르소나 1,000명 1회 생성, 캐싱)** (3~5일)
3. **E7 — 워밍업 자기소개 라운드 강화** (반나절)
4. **M1 + M3 — DCS/RDS 자동 측정 + Run 통합 PDF 에 게이지 표시** (2~3일)
5. **E11 — Calibration 풀 누적 시작 (대시보드: study 별 Calibration 누적 수)** (반나절)

**총 약 1~2주 작업으로 응답 현실성 평가·향상 인프라 v1 완성 가능.** 이후 Phase B (금융 도메인 보강)로 들어가 iM뱅크 사내 채택의 결정적 신뢰도 자료(부부장 "이게 정확해?" 무력화) 를 마련한다.
